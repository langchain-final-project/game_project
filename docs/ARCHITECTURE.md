# 구조와 데이터 흐름

현재 사람 입력은 `InputAdapter → GameApp → RealtimeGameCore.step`, 자유 이동 학습은 `RealtimeMansionEnv → RealtimeGameCore.step`으로 연결됩니다. 연속 이동 코어는 벽·닫힌 문에 몸체가 겹치지 않도록 소수점 좌표를 갱신하고 `GameCore._transition`의 수집·접촉·정산 규칙을 공유합니다. `snapshot → field/menus`는 읽기 전용이며 `outcome → Campaign.settle → SaveStore`에서만 지속 보상이 확정됩니다.

명령 하나는 1/60초이고 고양이는 한 방향으로 1/18칸 이동합니다. 세계 시간은 18명령마다 1틱(0.3초) 흐릅니다. 새 방향은 현재 칸의 중심에 도착할 때까지 기다리지 않습니다. 고양이 몸체의 반폭은 0.28칸이며, 벽에 닿으면 해당 축의 이동을 제한합니다. 점수·수집·유령 접촉·E 상호작용은 고양이 중심이 차지하는 칸으로 판단하며 매 이동 프레임 검사합니다. 보호·아이템 타이머와 유령 이동은 세계 틱에서만 갱신합니다. 틱 사이에 획득한 아이템도 즉시 적용되고 다음 세계 틱부터 차감됩니다.

기존 `GameCore.step` / `MansionEnv`는 한 명령이 한 칸·한 세계 틱인 검증 모드로 남습니다. `GameApp(movement_mode='grid')`는 기존 컨트롤러 회귀 검사에 사용합니다. 경로 도구와 과거 경로 증거는 이 모드의 결과입니다. 자유 이동의 안전성·난이도는 별도로 검증해야 하며 기존 경로 탐색기는 연속 이동 코어를 거부합니다.

## 역할별 경계

| 모듈 | 책임 | 포함하지 않는 것 |
|---|---|---|
| core / realtime / levels | 결정적 상태 전이, 연속 이동, 레벨 데이터 검증 | 화면·시간 측정·파일 저장·ML |
| app / input | 키 입력, 고정 이동 프레임, 메뉴, 포커스 상실 일시정지 | 별도 충돌·점수 판정 |
| campaign | 완료/사진/배지/꾸미기, 원자적 정산 | AI 훈련 보상 |
| env | numpy 관측, Gym 종료/보상 | Pygame·사람 세이브 |
| ui | 공통 그림과 텍스트, 위치 보간, 표정 | 스냅샷 수정 |

## 필수 물건과 지속 보상

레벨 JSON의 quest가 미션 이름·배치·복원 미리보기의 기준입니다. 스토리는 해당 데이터를 읽어 임무와 복원 문구를 맞춥니다. 수집 시 `collected`만 바뀝니다. 귀환 실패 시 사진과 복원은 지급되지 않습니다. COMPLETE를 한 번 정산하면 사진/복원은 영구 기록됩니다. 재도전으로 기록과 배지를 개선할 수 있고 사진은 중복 지급하지 않습니다.

기존 저장 형식의 구조는 유지했습니다. v0.1 기록이 새 물건 조건의 완료로 오인되지 않도록 기본 저장 파일 이름을 `save_v02.json`으로 분리했습니다. 이전 저장을 자동 변환하거나 삭제하지 않습니다. 명시적인 `--save-path`로 옛 파일을 지정하면 사진/완료 내역은 호환 로더가 읽을 수 있으나 새 규칙의 플레이 증거는 아닙니다.

## 화면과 애니메이션

1280×720 논리 화면을 창 크기에 맞춰 레터박스로 표시합니다. 자유 이동 고양이는 `motion.position`을 바로 그리며 추가 위치 보간을 하지 않습니다. 걸음은 실제 이동 거리로 진행합니다. 순찰·추격 유령은 세계 틱의 이전·현재 정수 좌표 사이만 보간합니다. `facing`, `mood`, 시각용 경과시간은 게임 판정에 들어가지 않습니다.

고양이는 `cat_sprites.py`가 `assets/art/character/kkamang.png`의 비균일 영역 28개(대기 4개, 걷기 24개)를 읽어 256×288 캔버스의 동일 몸통·발 기준으로 정렬합니다. 방향별 6프레임은 이동 거리로 선택하며, 멈추면 해당 방향의 대기 이미지를 사용합니다. 캐시로 원본 로딩과 프레임 크기 조절을 반복하지 않습니다. 기존 `cat_frame`/`cat` 호출 형태를 유지해 탐사·메뉴 초상화가 같은 PNG를 사용합니다. 로비와 대화 화면의 정적인 까망이 그림은 별도의 `lobby/character.png`를 사용합니다. 표정과 목도리 색상 인자는 현재 이미지 선택에 영향을 주지 않으며, 피격 중 걷기와 별도 보호막은 유지합니다. 그림 크기 조정은 물리 몸체나 관측 계약을 바꾸지 않습니다.

로비는 `ui/lobby.py`가 저장된 `completed` 목록을 읽어 `assets/art/lobby/before.png`에 `item.png`와 `character.png`의 영역을 합성합니다. 처음에는 중앙 러그에 까망이만 있고, 1·4·7스테이지 완료 시 A·C·B 유령이 각각 합류합니다. 물건은 1~11스테이지 완료 시 수건 선반·지도·발자국 사진·정원 안내서·스카프 고리·씨앗 주머니·악보·찻잔·커튼 끈·담요·마지막 악보 순서로 누적됩니다. 수건 선반은 왼쪽 책장에, 잃어버린 악보는 오른쪽 책장에 배치합니다. 12개 스테이지를 모두 완료하면 캐릭터가 포함된 `after.png` 원본을 표시하며 이미지를 중복 합성하지 않습니다. 처음 모습 보기에서는 진행도를 바꾸지 않고 까망이만 있는 방을 보여줍니다. 앨범 사진도 같은 로비 렌더러로 해당 단계의 장면을 캐시합니다. 대화 배경에서는 로비 캐릭터를 숨겨 큰 초상화와 겹치지 않도록 합니다. 로비 그림은 고정된 원본 색상을 사용하고, 기존 꾸미기 선택과 잠금 해제 기록은 유지합니다.

대화 화면의 까망이와 A·B·C 유령은 `lobby.py`의 `draw_story_character()`가 `lobby/character.png`에서 읽습니다. `menus._story_ghost_id()`는 현재 화자가 보송·이파리·도레일 때만 각각 A·B·C를 반환하며, '이야기' 등 유령 화자가 아닌 대사에는 유령을 표시하지 않습니다. 이 규칙은 프롤로그에도 적용되고 까망이는 계속 표시됩니다. 가운데 물건은 `draw_story_item()`이 스테이지 ID로 `STORY_ITEMS`의 영역을 선택하므로, `story.emblem`의 종류가 같아도 각 단계의 PNG가 표시됩니다. `STORY_ITEMS`는 로비의 1~11스테이지 물건과 대화용 12스테이지 정원문을 포함합니다.

유령은 `ghost_sprites.py`가 A/B/C를 `a.png`/`b.png`/`c.png`에 연결합니다. 각 8방향 자세를 몸체 하단 기준으로 정렬하고 캐릭터별 같은 배율로 캐시합니다. 탐사에서는 실제 이전·현재 정수 좌표로 상하좌우 자세를 선택하며, 부유 효과는 화면 y좌표에만 더합니다. `GameApp.ghost_facings`는 마지막 이동 방향을 보관해 추격 정지나 일시정지 재개 시 자세가 정면으로 돌아가지 않게 합니다. 이 정보는 코어·학습 관측·리플레이 행동에 포함하지 않습니다. 주민 변형 값 0/1/2는 보송/이파리/도레로 기존 호출 형태를 유지하며 탐사와 호감도 화면에서 같은 세 PNG를 표시합니다.

## 수정 시 동기화

quest 필드를 바꾸면 JSON 스키마·Python validator·env 인코더·briefing/HUD·귀환 정산·경로 테스트를 함께 확인하세요. 위치/시간만 바꿔도 `config_hash`가 달라지므로 이전 경로·기록을 새 맵의 검증 결과로 재사용하면 안 됩니다. 필드 의미나 차원이 바뀌면 observation version을 올리고 모델을 다시 학습해야 합니다.
