# 강화학습 연결 준비와 검증 범위

현재는 환경 구현과 비교 정책 검증까지입니다. PPO/DQN 학습, 모델 성능 향상, 미지 맵 일반화는 아직 검증하지 않았습니다.

## 현재 게임의 자유 이동 계약

`from kkamang.env import RealtimeMansionEnv`로 현재 데스크톱 게임과 같은 이동을 학습합니다. `Discrete(6)`, `Box(0,1,(623,),float32)`, 관측 버전은 `vector_v6_realtime`입니다. 한 행동은 1/60초이고 18행동마다 유령·게임 시간·효과 타이머가 0.3초 세계 틱만큼 진행됩니다. 따라서 같은 제한시간의 에피소드에도 칸 단위 환경보다 최대 18배 많은 명령이 필요합니다. 실제 학습 소요 시간과 성능은 측정하지 않았습니다. `max_episode_steps`도 세계 틱이 아닌 이동 프레임 수입니다.

앞의 620개 필드 형식은 아래 칸 단위 계약과 같고, `620:622`에 실제 소수점 중심 좌표 `(x/15,y/8)`, `622`에 다음 세계 틱까지의 위상을 추가합니다. `432:434`는 현재 중심이 차지하는 정수 칸입니다. 반폭 0.28칸 몸체가 벽·닫힌 문을 넘지 못하며, 틱 사이에도 획득·접촉·E를 검사합니다. 아이템은 즉시 활성화되고 남은 횟수는 세계 틱에서 감소합니다. `data/levels/realtime_observation_contract.json`에 명세가 있습니다. 620차원 모델은 그대로 불러올 수 없습니다.

자유 이동에서도 보상은 기존 완료·귀환 온기 및 선택적 실제 피해 패널티입니다. 방향 변경·키 반복은 유령/타이머를 추가 갱신하지 않습니다. 프레임 진행률과 실제 중심 좌표가 관측되어 같은 칸 안의 서로 다른 상태를 구별할 수 있습니다.

`tools/evaluate.py`는 이제 기본 CLI 실행에서 자유 이동을 평가합니다. 기존 칸 단위 평가는 `--control-mode grid`로 명시합니다. `tools/plan_routes.py`와 기존 36개 경로는 계속 칸 단위 검사이며, 아래 과거 결과를 자유 이동의 무피해·성능 근거로 재사용하지 않습니다.

### 현재 자유 이동의 비교 정책과 경로 검증

```sh
# 무작위/규칙 기반 정책을 같은 stage/episode seed와 초기 위상에서 비교
python tools/evaluate.py --control-mode realtime --episodes 1 --stages 1 2 --output reports/local/realtime_evaluation

# 12개 방에서 필수 물건+온기 4점 이상, 접촉 없는 완료 경로 생성·재생
python tools/validate_realtime_routes.py --targets 4 --output reports/local/realtime_routes

# 높은 온기 목표와 무적 아이템 접촉 허용을 명시한 추가 검사
python tools/validate_realtime_routes.py --stages 3 11 --targets 10 14 --contact-policy item_invincible --output reports/local/realtime_rich_routes

# 생성한 60Hz 행동 기록 하나를 다시 재생
python tools/replay_validation.py --record reports/local/realtime_routes/replays/stage_01_target_04.json
```

`RealtimeGreedyPolicy`는 현재 코어를 복제해 이동의 **매 1/60초 프레임**을 검사합니다. 18프레임의 중심 간 이동, 짧은 대기, 1프레임 E로 경로를 구성하며, 중간 프레임의 접촉도 제외합니다. 평가에서는 실제 무적 아이템이 적용된 접촉만 허용하고, 경로 검증은 기본적으로 모든 접촉을 금지합니다. 피격 후 보호는 접촉 허용 근거가 아닙니다. 샛문 개방과 모든 칸 중간 회전을 탐색하지 않는 제한된 기준선입니다.

물건 회수를 우선하고 추가 수집마다 귀환 경로와 세계 틱 2개만큼의 여유를 확인합니다. `--target-warmth`의 기본값은 14이지만, 더 모을 경로를 찾지 못하면 온기 4점 이상의 합법적 완료로 귀환할 수 있습니다. 따라서 `complete_rate`와 목표 온기까지 달성한 `target_rate`를 구분합니다. 경로 검증은 요청한 목표 온기 이상·피해 0·접촉 정책 충족·전체 최종 스냅샷 재생 일치가 모두 필요합니다. 목표는 최소 온기이며 정확히 4점으로만 귀환한다는 뜻은 아닙니다. 탐색 실패는 맵 불가능성의 증거가 아닙니다.

CLI 탐색 예산은 목표당 realtime 128노드, grid 1,500노드가 기본입니다. `--max-search-nodes`로 동일 비교 예산을 명시할 수 있습니다. 경로 도구의 초기 위상은 기본적으로 설계값이며 `--randomize-phase`로 seed 변형을 사용합니다. 평가 도구는 기본 seed 변형, `--fixed-phase`로 설계값을 사용합니다. 위상 조건이 다른 결과를 같은 실험으로 비교하지 않습니다.

`episodes.csv`는 `episode_steps`(환경 명령 수), `physics_frames`(자유 이동만), `ticks_used`(세계 틱), 시뮬레이션 초, 확정 온기·100점·별·피해·접촉·물건 회수와 계산 시간을 구분합니다. `summary.json`은 제어 방식·관측 버전·설정 해시·구현 해시·탐색 예산과 요약을 기록합니다. `replays/`에는 실제 행동과 초기 위상, 새 기록의 전체 최종 상태 해시를 저장합니다. 출력은 기본적으로 Git에서 제외되는 `reports/local/`에 보관합니다.

이 기준선은 **오프라인 계획 도구**입니다. 경로 계산 중의 실제 대기 시간은 시뮬레이션 시계를 진행시키지 않습니다. `policy_compute_seconds`, 평균·최대 행동 계산 시간은 별도 기록하며, 실제 60Hz에서 실행 가능한 AI라는 주장으로 해석하지 않습니다. 무작위 정책도 매 프레임 새 행동을 뽑으므로 인간처럼 방향키를 오래 유지하는 정책은 아닙니다. 모델 체크포인트 로드·PPO/DQN 학습·미지 맵 일반화는 이번 도구에 포함하지 않았습니다.

`--max-episode-steps`는 외부 평가 중단이며, realtime에서는 프레임 수입니다. 외부 중단은 `truncated`, 게임 자체의 시간 초과는 `terminated`로 유지합니다. `evaluate()` 파이썬 함수의 기본 `control_mode='grid'`는 기존 호출 호환용이고, CLI 기본값은 `realtime`입니다. 새 코드에서는 제어 방식을 명시하세요.

## 기존 칸 단위 실행 계약

`pip install -r requirements-rl.txt` 후 `from kkamang.env import MansionEnv`로 사용합니다.
`reset(seed=...) → (obs, info)`, `step(action) → (obs, reward, terminated, truncated, info)`.
`Discrete(6)`, `Box(0,1,(620,),float32)`. Pygame 창 없이 반복 실행합니다.

| 인덱스 | 정보 |
|---|---|
| 0:144 | 벽 |
| 144:288 | 닫힌 문 |
| 288:432 | 귀환점 |
| 432:437 | 고양이 좌표·용기·보호·온기 |
| 437:441 | 남은 시간·시작 시간·온기 목표·모드 |
| 441:481 | 10개 온기 슬롯 |
| 481:587 | 유령 2개: 경로·위상·방향·이동 카운트다운 |
| 587:599 | 장치 2개: 장치/문 좌표·개방 여부 |
| 599:602 | 필수 물건 좌표·회수 여부 |
| 602:604 | 순찰 유령 A·B의 이동 간격 / 512 |
| 604:610 | 추격 유령 설정 유무·활성화·좌표·대기 시간·이동 간격 |
| 610:615 | 자석 설정 유무·획득 여부·좌표·남은 효과 틱 / 13 |
| 615:620 | 무적 설정 유무·획득 여부·좌표·남은 효과 틱 / 10 |

관측 버전은 `vector_v5_invincibility`입니다. 이전 610·615차원 모델은 그대로 연결할 수 없습니다. 순찰·추격 유령의 대기 시간과 이동 간격은 512로 나누어 표현합니다.

무적은 3번 [7,5], 5번 [12,2], 11번 [14,6]에 배치합니다. 획득한 틱부터 10틱 동안 피해만 방지하며 유령 이동·제한시간·추격 유령의 접촉 정지는 그대로 진행합니다. 획득 직후 관측에는 9틱이 기록됩니다. 기존 피격 후 3틱 보호와 별도이며 아이템 획득 보상은 추가하지 않습니다.

모든 방의 경로 탐색은 실제 GameCore 상태를 복제해 순찰·추격·아이템 획득·만료·추격 유령 정지를 계산합니다. 무적 아이템이 적용된 접촉만 허용하며, 아이템이 없거나 만료된 경우와 기존 피격 보호만 있는 경우에는 접촉을 제외합니다. 공통으로 정적 최단 이동과 순찰 BFS 후보를 먼저 실제 코어로 검증하고, 실패하면 목표당 최대 1,500회 힙 항목을 꺼내는 A* 탐색을 수행합니다. 검증된 후보를 먼저 채택하므로 최단 경로는 보장하지 않습니다. 별도의 안전 경로 검증은 계속 모든 접촉을 금지합니다. 이 기능은 학습 환경과 검증용 탐색이며 학습 성능 향상을 입증한 결과가 아닙니다.

자석은 2번 [3,4], 7번 [8,4]에 하나씩 배치됩니다. 밟은 틱부터 13틱 동안 고양이 중심 3×3의 +1·+3 온기를 수집하며, 벽·닫힌 문은 수집을 막지 않습니다. 획득 직후 스냅샷에는 남은 12틱이 기록됩니다. 대기·막힌 이동·상호작용도 효과 시간을 소비합니다. 흡입 그림은 UI 전용이며 점수는 해당 틱에 즉시 반영됩니다. 스테이지 시작/재도전 시 아이템과 효과를 초기화합니다.

`tools/plan_routes.py`는 자석 획득 및 인접 칸 수집을 후보로 탐색하고 실제 GameCore로 검증합니다. +3 미획득 경로는 자석의 원격 수집도 금지합니다. 빔 탐색이므로 최단 경로 보장은 없으며, 폭을 늘리면 다른 경로를 찾을 수 있습니다. `tools/evaluate.py`의 탐욕 정책은 `TimedGreedyPolicy(core=env.core)`로 생성하며 아이템 유무와 관계없이 같은 계획 방식을 사용합니다. 아이템의 실제 수집 이득과 귀환 경로를 확인하고 귀환에 2틱의 여유를 둡니다. 목표 순서 전체와 샛문 개방은 최적화하지 않습니다.

### 통일된 평가 정책으로 비교하기

```sh
python tools/evaluate.py --control-mode grid --episodes 30 --seed 20261018 --max-search-nodes 1500 --output reports/local/unified_evaluation
```

정책 버전은 `unified_core_v1`입니다. 모든 스테이지에 같은 탐색 예산과 접촉 허용 규칙을 적용합니다. 무작위·탐욕 정책은 스테이지와 회차마다 같은 seed 및 초기 순찰 위상을 사용합니다. `--fixed-phase`를 지정하면 설계된 초기 위상을 유지합니다. 게임 규칙·보상·온기·유령·아이템 배치·시간 설정은 평가 실행으로 바뀌지 않습니다.

`episodes.csv`에는 성공 여부, 확정 온기, 피해·접촉, 사용/남은 틱, 세 가지 점수와 별, 아이템 획득 및 자석 수집량, 초기 위상과 설정 해시를 기록합니다. `summary.json`은 스테이지별 결과와 평가 구현 해시·탐색 예산을 보관합니다. 점수 평균은 실패 기록의 0점도 포함하며, 완료한 판의 평균 사용/남은 틱은 별도 필드로 구분합니다. 개별 스테이지 점수는 12개 대표 기억에 대한 실제 엔딩 달성률을 뜻하지 않습니다.

`search_node_limit`는 탐색 한도 도달, `search_exhausted`는 해당 목표에 대한 탐색 소진, `search_insufficient_time`은 남은 시간보다 정적 최단 거리가 긴 경우입니다. 이 횟수들은 한 판에서 시도한 여러 후보 경로의 통계이며, 그 판 실패의 원인을 증명하지 않습니다. 실제 종료 원인은 `end_reasons`에 별도로 집계합니다. 검증된 계획이 없을 때에는 안전한 한 행동을 찾고, 그것도 없으면 `no_safe_action_steps`를 기록합니다. 탐색 실패나 특정 탐욕 정책의 실패를 맵 자체의 불가능성으로 해석하지 않습니다.

2026-10-18에 11번 무적 아이템 추가 전 설정으로 위 명령을 실행한 비교에서는 탐욕 정책 360/360 완료·모든 판 피해 0, 무작위 정책 0/360 완료였습니다. 당시 모든 레벨과 게임 규칙·보상 파일을 수정 전 해시와 비교해 변경이 없음을 확인했습니다. 결과는 `reports/local/unified_evaluation/`의 `analysis.md`, `summary.json`, `episodes.csv`에 있습니다. 해당 결과를 새 11번 설정의 결과로 재사용하지 않습니다. 단일 탐욕 정책의 결과이며 강화학습 성능이나 사람 체감 난이도를 증명하지 않습니다.

조건과 다음 전이에 필요한 시간·순찰 위상·문·물건 보유 여부를 관측합니다. 목도리, 앨범, 대사, 복원 소품은 전이에 영향이 없으므로 넣지 않습니다. 사람도 전체 맵·순찰 경로·다음 이동 예고를 봅니다.

## 보상과 종료

기본 훈련 보상은 종료 때 `2 * 성공 여부 + 확정 온기/14`. 실패/중단은 0, 수집·제자리 E·문 반복 조작은 중간 보상 0입니다. 선택 옵션 `safety_coefficient`는 실제 피해 횟수에만 패널티를 줍니다. 기본값은 0입니다.

게임 자체 제한시간은 관측된 게임 규칙의 실패이므로 `terminated=True`. 외부 실험 한도 `max_episode_steps`는 `truncated=True`이며 성공/점수를 지어내지 않습니다.

이 보상은 **희소 보상**입니다. 무작위 비교 정책이 120판에서 성공하지 못했으므로 처음부터 12개 방을 섞어 기본 PPO로 잘 배운다고 보장하면 안 됩니다. 수업에서 학습 전 다음을 결정하세요.

- 먼저 stage 1 한 방에서 고정 평가로 작은 학습 실험을 수행합니다.
- 학습용 시간 여유를 늘릴 경우 별도 환경/설정 해시로 구분하고, 기본 모드 평가를 따로 유지합니다.
- 탐험이 막히면 성공 행동열을 활용한 모방학습 초기화 또는 potential-based shaping을 별도 실험으로 비교합니다. 현재 게임/보상에는 자동 적용하지 않았습니다.
- gamma<1은 빠른 귀환과 추가 수집 사이의 선호를 바꿉니다. 최종 점수 최대화가 목적이면 할인 영향을 확인해야 합니다.
- 성공률과 확정 온기, 피해, 사용 틱, 필수 물건 회수율을 함께 봅니다. 미귀환 보유 온기를 성공 점수로 쓰지 않습니다.
- 학습/검증/평가 seed를 분리하고 3개 이상 학습 seed, 같은 step 예산으로 비교합니다. 이는 후속 권장 프로토콜이며 수행 결과가 아닙니다.

## 이전 v0.2 설정의 기준선

아래 결과는 추격 유령이 추가되기 전 v0.2 설정에서 측정했습니다.

`tools/evaluate.py`는 공개 경로/위상만 사용하는 시간 고려 탐욕 정책입니다. 필수 물건부터 회수하고 안전하게 귀환할 여유가 있는 온기를 고릅니다. 신경망이나 학습 모델이 아닙니다. 12개 고정 맵, 방마다 10개 랜덤 초기 순찰 위상 seed, 두 정책 합계 240판을 실행했습니다. 결과는 `reports/evaluation_v02/`입니다. 무작위 0/120 성공, 탐욕 120/120 성공, 탐욕 평균 확정 온기 약 13.03점입니다.

이 기준선이 강하므로 학습 모델이 단순히 random보다 좋다는 것만으로 기획의 우수성을 주장하지 마세요. 동일 조건의 탐욕 기준선과 성능·추론시간·일반화를 비교해야 합니다. 테스트 맵을 따로 만들기 전에는 새로운 맵에 잘 대응한다고 주장할 수 없습니다.
