# PPO 변경 내용을 공부하는 순서

ZIP은 원본 자료이며 그 안의 실행 안내를 자동으로 실행하지 않았습니다.
이번 변경은 사용자의 요청에 따라 별도 `ppo_2388` 폴더에만 적용했습니다.
최초 작업은 설치·모델 생성·모델 검사·학습 전 단계까지만 준비했습니다.
이후 사용자의 학습 중 발생한 Windows 파일 잠금 오류를 보완했습니다. 아래 7번 항목을 참고하세요.

## 1. 환경과 신경망을 유지한다

`game_source/`, `environment.py`, `refinement.py`, 관측 코드, `policy.py`는 원본 그대로입니다.
`UnifiedA2CPolicy`는 이름에 A2C가 있지만 CNN·MLP와 이산 행동 분포를 정의한
`MultiInputActorCriticPolicy` 하위 클래스라 PPO에도 같은 신경망으로 전달할 수 있습니다.
학습 알고리즘은 신경망 클래스 이름이 아니라 모델을 생성하는 `PPO(...)`가 결정합니다.

## 2. 학습 알고리즘을 바꾼다

`a2c_game/train.py`와 `fresh_training.py`의 모델 생성·복원은 `PPO`를 사용합니다.
PPO에 없는 `use_rms_prop` 인자는 제거했습니다. 기존 정책의 Adam 설정은 그대로 사용합니다.
`PPO_SETTINGS`를 새 실행의 `config.json`에도 저장해 어떤 PPO 설정으로 실행했는지 남깁니다.

공통 설정의 `a2c` 키는 환경에서도 gamma 등을 읽으므로 이름을 일괄 교체하지 않았습니다.

## 3. 경험 수집 횟수와 반복 학습 횟수를 구분한다

```text
환경 4개 × 각 32행동 = 새 경험 128개 = rollout 1회
PPO: 그 128개 전체를 10 epochs 학습 = Adam 갱신 10회
```

SB3의 `_n_updates`는 PPO에서 epochs를 누적합니다.
이를 A2C의 갱신 횟수처럼 사용하면 같은 경험량에 도달하기 전에 평가하거나
저장된 Adam 상태를 잘못 판정할 수 있습니다.

- `completed_rollouts()`는 `_n_updates // n_epochs`로 완료한 rollout 수를 계산합니다.
- `assert_integrity()`는 완료한 rollout과 환경 스텝, epochs, Adam 상태를 함께 검사합니다.
- `save_resume()`의 버려진 경험 수 계산도 rollout 단위로 고쳤습니다.
- `session_updates`는 원본처럼 rollout 수를 받으며 내부에서 epochs로 환산합니다.
- 엔트로피 조정 간격과 회차별 목표도 원본의 경험량을 유지하도록 환산합니다.

예를 들어 3,200개의 새 경험을 학습했다면 rollout 25회, PPO epochs 250회입니다.
원본의 로그 간격 25를 epochs로 잘못 읽으면 경험 320개마다 기록하게 됩니다.

## 4. 로그와 평가 기록을 맞춘다

PPO의 정책 손실 키는 `train/policy_gradient_loss`입니다.
출력 로그의 `policy_loss` 필드에는 이 값을 기록해 기존 화면에서 사용할 수 있게 했습니다.
`evaluation.py`와 학습 메타데이터의 알고리즘 이름은 `PPO`로 기록합니다.
저장된 원본 A2C 결과 파일은 다시 쓰거나 PPO 결과로 표시하지 않습니다.

## 5. 실행 명령과 화면을 새 PPO 실험에 연결한다

`team.py`의 `prepare`, `check`, `train`, `watch`, `dashboard`는 새 PPO 실행을 대상으로 합니다.
`check`는 새 모델의 입력·환경·파일을 확인하고 학습은 하지 않습니다.
`play.py`에 따로 있던 모델 로더도 `PPO.load()`로 변경했습니다.
관람 화면과 대시보드의 알고리즘 표기 및 설정 표를 PPO로 맞췄습니다.
원본 모델의 선정 스텝인 971만 스텝을 새 PPO 성과처럼 표시하던 고정 문구도 제거했습니다.

## 6. 다음 실행은 사용자가 한다

실행 명령은 [README.md](README.md)에 있습니다.
최초 준비 과정에서는 실제 PPO 모델을 생성하거나 학습하지 않았습니다.
이후 파일 잠금 오류 수정에서는 사용자가 저장한 체크포인트의 모델·Adam 상태 및 전12맵 연결을 검증했습니다.

## 7. Windows 파일 잠금으로 학습이 중단되지 않게 한다

`file_io.py`에 공통 저장 함수를 추가했습니다.

1. `replace_with_retry()`는 접근 거부와 공유 잠금에 한해 최대 5초 동안 파일 교체를 재시도합니다.
   디스크 용량 부족 등 다른 오류는 즉시 전달합니다.
2. `write_json()`은 매번 고유한 임시 파일에 완전한 JSON을 쓴 뒤 원자적으로 교체합니다.
   교체가 실패해도 기존 JSON을 먼저 삭제하거나 덮어쓰지 않습니다.
3. `LiveJSONWriter`는 현황 갱신에 최대 0.05초만 재시도합니다.
   실패하면 2초 뒤 다시 시도하며 학습 콜백은 계속 진행합니다. 같은 장애의 경고는 반복 출력하지 않습니다.
4. 학습·평가·최신 실행 포인터가 공통 JSON 저장 함수를 사용합니다.
   재개 체크포인트와 선정 모델 교체에도 동일한 재시도 함수를 적용했습니다.
5. 원래 실패한 실행 폴더의 체크포인트·설정·기록·소스 스냅샷은 보존했습니다.
   별도의 `_io_retry_v1` 재개 폴더에 같은 모델과 학습 기록을 복사하고 수정 소스를 기록했습니다.
   소스 해시 검사는 그대로 유지합니다. 원본과 변경 내역은 `io_retry_resume.json`에 남깁니다.

검증은 `tests/test_file_io.py`에서 수행했습니다.
실제 Windows 파일 핸들로 교체를 막았다가 해제하는 경우, 계속 잠긴 현황 파일,
동시 저장, 시간 제한, 기존 JSON 보존, 학습 콜백 지속 등을 포함한 테스트 10개가 통과했습니다.
복사한 체크포인트의 96,128스텝·7,500 epochs와 Adam 상태를 확인했고 전12맵 연결 검사도 통과했습니다.
이 검증에서 추가 학습 업데이트는 수행하지 않았습니다.
