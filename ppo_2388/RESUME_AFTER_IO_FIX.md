# 파일 잠금 오류 수정 후 재개

`live.json` 교체가 잠시 거부되면 재시도하도록 수정했습니다.
현황 파일이 계속 잠겨 있어도 해당 화면 갱신만 건너뛰고 학습을 계속합니다.
체크포인트·메타데이터·평가 JSON·선정 모델 교체에도 재시도를 적용했습니다.

## 보존한 상태

- 원래 실패한 실행: `runs/seed_11_20261102_230005_281926`
- 수정 코드로 재개할 복사본: `runs/seed_11_20261102_230005_281926_io_retry_v1`
- 저장된 환경 스텝: 96,128
- 완료한 PPO epochs / Adam 갱신: 7,500
- 완료한 rollout 수: 750
- 체크포인트: `resume_A.zip`

원래 실패한 실행 폴더의 파일은 수정하지 않았습니다.
복사본의 체크포인트·설정은 원본과 같은 해시입니다.
새 재개 폴더에는 변경된 소스 스냅샷과 그 해시를 기록했으며, 기존 해시 검사를 해제하지 않았습니다.
변경 전 출처와 변경 파일별 해시는 복사본의 `io_retry_resume.json`에 있습니다.
`runs/latest.json`은 새 재개 폴더를 가리키도록 설정했습니다.

## 실행

현재 프로젝트 루트의 `.venv`가 활성화된 터미널에서 다음 명령을 실행하세요.

```powershell
Set-Location 'C:\Users\gkoh\.vscode\KDT\game_project\ppo_2388'
python run.py train --run runs/seed_11_20261102_230005_281926_io_retry_v1 --hours 8
```

`python run.py train --hours 8`도 최신 실행 포인터를 통해 같은 복사본에서 이어갑니다.
대시보드와 관람 명령 역시 기본값으로 새 재개 폴더를 사용합니다.
이미 켜 둔 대시보드·관람 프로세스는 기존 폴더를 계속 보고 있으므로 종료 후 다시 실행하세요.

## 검증

파일 잠금·재시도·현황 실패 시 학습 지속 등 테스트 10개를 통과했습니다.
실제 Windows 파일 잠금 테스트를 포함합니다.

```powershell
..\.venv\Scripts\python.exe -B -m unittest discover -s tests -p test_file_io.py -v
```

새 재개 폴더의 소스 해시, 체크포인트 해시, 모델·Adam 상태, 전12맵 입력 연결을 검증했습니다.
검증 결과는 새 재개 폴더의 `verification/check.json`에 있습니다.
검증 과정의 추가 학습 업데이트는 0회이며 장시간 학습은 시작하지 않았습니다.
